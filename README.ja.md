## ジャービスが他社のサービスだったら？

トニー・スタークが長いあいだジャービスと働いてきたとします。自分の文脈を共有し、判断を保留し、仕事を任せながら、一緒に働く方法を積み重ねてきました。

そこに、もっと優れた AI が登場します。

**トニーはその AI を使うために、ジャービスまで失う必要があるのでしょうか。**

知能の提供者が変わるという理由だけで、ジャービスが覚えている自分の文脈、まだ終わっていない仕事、任せた権限、積み重ねた働き方まで最初から作り直すべきでしょうか。

**AI は替えられても、自分のパーソナルエージェントは自分のものであり続けるべきです。**

Personal AgentOS は、自分でインストールして管理するオープンソース環境でこの考えを探ります。PA の文脈・未完の仕事・権限・実行の根拠は自分の手元に残し、その下で働く AI は替えられるようにします。

目標は履歴が長いだけのチャットボットではありません。AI が替わっても続く、一つのパーソナルエージェントです。

**同じ PA。違う AI。**

まず動かしてみたい場合は [まずは試してみる](#まずは試してみる) へ進んでください。このページの残りは、プロジェクトが目指すものを説明します。

## ジャービスが他社のサービスだったら？

トニー・スタークがジャービスと重ねた会話や進行中の仕事を考えてみてください。もしジャービスが他社の AI サービスなら、その会社がモデルを替えたりサービスを終えたりすると、トニーについての文脈や任せた仕事まで失うべきでしょうか。[白書の思考実験](docs/whitepapers/whose-agent.ko.md)は、知能をどこから得るかと、本人の記憶・仕事・権限を誰が引き継ぐかを分けて問いかけます。

AgentOS は、記憶、進めている仕事、与えた権限を自分の環境に保持します。どの AI を使い、どの情報を渡し、どこまでアクセスを認めるかを自分で決めます。異なる専門性を使っても、中心にいるのは同じ自分です。より良い AI が登場しても最初からやり直さず、自分のエージェントにできることが広がる。そのための仕組みです。

この管理のうち二つは現在のリリースに含まれています。自分が選んだ AI が事実を記憶に保存すると、保存後に知らせて正確に取り消せるようにします。また、任せた仕事ごとに、自分のどの情報を使い、どこへ送ったかを記録します。

ローカルファースト（local-first）はローカル限定（local-only）ではありません。ローカルモデルと外部のモデルを選べます。外部のモデルを使う場合、依頼に使う文脈はその提供者へ送信されます。

## 任せた仕事はどう続くのか

*次の会議は製品の方向性を示す架空の例です。現在の Homebrew 版でこの一連の動作が観測されたわけではありません。*

「来週のプロジェクト会議を気にかけておいて。提案の結論を出したい」と頼んだとします。PA は、アクセスを許された予定の招待、提案書、以前の決定記録を同じ会議に結び付け、未決事項を見つける方向で動きます。招待を受けただけで、出席や後続作業を引き受けたとは見なしません。会議前には判断に必要な資料を準備し、後で本人がメモを渡したら残る仕事を更新します。後続メールは**下書き**として用意できますが、下書きは送信ではありません。送信権限がなければ先に尋ね、ツールが実際の結果を確認するまで「送った」とは報告しません。

**PA はあなたが会話するパーソナルエージェント、AgentOS はその文脈・残る仕事・権限・根拠を自分の環境に保つ基盤です。** 判断層が必要な AI とツールに仕事を任せ、結果を確かめます。下で働く AI が替わっても、同じ PA と任せた仕事を引き継ぐことを目指します。**同じ PA。変わる AI。**

長い会話履歴だけでは仕事を引き継げません。**一つの会議**には日時・場所・参加者という**メタデータ**があります。**オントロジー**は、その会議とほかの対象との関係を区別します。

- **予定としての会議：** いつ誰と会い、何を準備するか。
- **プロジェクトにおける同じ会議：** 提案のどの判断がまだ残っているか。
- **約束につながる同じ会議：** 誰が後続作業を提案し、誰が実際に引き受けたか。

三つの別々の会議ではなく、出典のある一つの会議に結び付く異なる関係です。会議の識別・日時・招待には記録があり、緊急度や責任についての判断には視点と根拠が必要です。招待は引き受けた約束ではありません。記録がないことを「起きていない」と決めつけず、出典が衝突したら片方で上書きしません。未決事項は仕事として引き継ぎ、**確認できない権限は実行許可と見なしません。** 根拠は下書きと実際の送信を区別します。

AgentOS は、事実、役割ごとの解釈、任せた仕事、実際の権限と実行の根拠を、本人が管理する構造で結び付けようとしています。仕事が中断したり AI が替わったりしても、次にすべきことを見つけ直せるようにするためです。同じ原則は会議以外にも当てはまり、[アーキテクチャとオントロジー](docs/personal-agentos-architecture.en.md#facts-and-role-interpretations)では口座残高の例で説明しています。これらは設計上の例であり、観測済みの実行ではありません。状況の変化に先回りして注意を向けることは、現在の反応型 Presence を超える今後の方向であり、現時点で常時監視ができるという主張ではありません。

## 日常の短い言葉にも、同じ PA

*オーナーのパイロット会話をもとに、要約と匿名化を加えて再構成した図です。その会話の証拠記録ではなく、図中の地図・ショッピング連携は提供済みの機能ではなく製品の方向性です。*

下の図は、PA との会話を三つの場面にまとめたものです。位置を共有して帰り道の夕食を探す場面、ゴルフベルトを比較してカート操作前にアカウントへのログインを求める場面、レストランの写真から近くの散歩へ話が続く場面を示します。説明用に編集した再構成画像であり、製品画面そのものの撮影や連携機能の提供実績ではありません。

[日本語画像をフルサイズで見る](docs/assets/readme/owner-pilot-conversation.ja.png) · [元の参考画像を見る](docs/assets/readme/owner-pilot-conversation-reference.jpg)。

図は会話を短くまとめたものです。提案が意味を持つには、本人が許可した関連情報を使い、足りない情報や古い情報を確認し直す必要があります。

1. **帰り道の夕食：**「帰りに夕食を食べようかな」の「帰り道」は、現在地から自宅へ向かう経路です。職場・自宅の場所を保存してよいか、使ってよいか、今どこにいるか、同行者と時刻を確かめます。図では PA が現在地を尋ね、経路・距離・営業時間を考慮した三店を示し、本人は二番目を選びます。
2. **このベルトを探して：** 写真に似ているだけではよい選択とは限りません。共有された服の種類・色、好みや予算があれば比較に使い、なければ必要なことだけ尋ねます。図では三本を比べ、選んだ一本をカートに入れる前にアカウントへのログインを求めます。カートへの追加と支払いは別の行動です。カートに入れる段階そのものは実行型エージェントも行います。違いは、PA が自分の文脈と好みを選択に反映し、クリックではなく自分のアカウントと権限の境界で止まることです。
3. **ここで夕食中。その後は？：** 店の写真と共有された現在地に加え、誰と何のために来たのか、時刻と天気によって提案は変わります。知らない状況を作り上げず、必要なら確認して散歩・カフェ・バーを提案します。散歩を選んだら経路と営業時間を改めて調べます。

三つの場面に共通するのは、**言葉と写真 → 出典・時刻のある許可された文脈 → 必要な質問とツール → 行動の範囲 → 確認した結果**という流れです。図はこの関係を示すもので、すべての情報をすでに収集したことや、地図・買い物の連携が提供済みであることは意味しません。

数時間あいて交わす短い言葉にも、同じ継続性が必要です。

> 「コーヒー、もうなくなりそう。」<br>
> 数時間後：「今から出るんだけど、途中で買えるところあるかな？」<br>
> その後：「時間ないな。前と同じものを買っておいて。」

目指す姿はシンプルです。PA が何を買う話なのか、「前と同じもの」が何なのかを引き継いで理解し、関連する文脈を使い、足りない情報や権限は必要になった時に尋ねます。自分は話を続ければよく、作業の手順を組み立てる必要はありません。

## まずは試してみる

公開版で自分のモデルと会話を始められます。上の会議の一連の場面が、この版で検証済みという意味ではありません。

macOS で [Homebrew](https://brew.sh) を使う場合：

```sh
brew install jongtae/agentos/agentos
agentos start
```

1. ブラウザーで [http://127.0.0.1:8787](http://127.0.0.1:8787/) の設定画面が開いたら、**바로 시작하기**（今すぐ始める）を選びます。
2. 自分のモデルを接続し、接続テストを完了します。ツール呼び出しに対応したローカルの Ollama モデル、または自分の API 利用権限で OpenAI、OpenAI 互換サービス、Anthropic を使えます。API キーの代わりに Codex や Claude Code のサブスクリプションに任せることもできます（[QUICKSTART](QUICKSTART.md)）。設定画面は現在韓国語です。
3. **설정 → 외부 연결**（設定 → 外部接続）で、BotFather で作った自分のボットのトークンを入力して接続します。表示されたペアリングリンクを Telegram で開き、**開始**を押します。
4. その Telegram のチャットで、**「今週中に提案書の草案を仕上げたい。次にやることをいくつかの段階に整理して。」** と話しかけてみてください。

Python は Homebrew が一緒にインストールします。モデルの利用環境は別途用意してください。会話中は `agentos start` を実行したままにします。モデルの設定、ファイル作業、Telegram、最新ソースからの実行手順は [QUICKSTART](QUICKSTART.md) にあります。

**現在の段階：** Homebrew からは、タグを付けた main コミットの **v1.1.1**（2026-10-07）が入ります。上の会議や買い物の場面は、この版で一連の動作が検証済みという意味ではなく、製品の方向性を示す例です。[リリース内容](docs/release-manifest.json)に含まれるソースとインストール検証を記録し、[現在の状態](docs/product-status.en.md)では利用可能な動作・テストの根拠・オーナーパイロット・今後の方向を分けて説明します。
