## 任せた仕事を引き継ぐパーソナルエージェント

アシスタントは質問に答え、コンピューターエージェントは指示された操作を実行します。しかし、暮らしや仕事は、完成した質問や一度きりの指示だけでは終わりません。会議の話をし、決定を保留し、数日後に戻ったときにも、次にすべきことが残っています。

**Personal AgentOS は、自分でインストールし、管理できる環境で、自分と任せた仕事を引き継ぐパーソナルエージェント（PA）を作ろうとするプロジェクトです。** 依頼の意図、未解決のこと、待っていることを保持する。その先には、次の仕事を準備し、必要なときに話題を戻し、権限が必要な行動の前には本人に尋ねる姿を目指します。

このように続く関係を **Presence** と呼びます。アシスタントとしての支援は出発点であり、目標は仕事の種類や AI が変わっても同じ PA が続くことです。親しみやすい口調ではなく、保持された文脈・仕事・権限がその土台です。

## 自分のエージェントを、自分の環境に

エージェントがさまざまな仕事を助けるほど、その記憶を誰が持ち、できることを誰が決めるかが大切になります。積み重ねた文脈が、特定の会社やモデル、一度の会話だけに縛られてほしくありません。

AgentOS は、記憶、進めている仕事、与えた権限を自分の環境に保持します。どの AI を使い、どの情報を渡し、どこまでアクセスを認めるかを自分で決めます。異なる専門性を使っても、中心にいるのは同じ自分です。より良い AI が登場しても最初からやり直さず、自分のエージェントにできることが広がる。そのための仕組みです。

ローカルファースト（local-first）はローカル限定（local-only）ではありません。ローカルモデルと外部のモデルを選べます。外部のモデルを使う場合、依頼に使う文脈はその提供者へ送信されます。

## 任せた仕事を続けるために

「来週のプロジェクト会議を気にかけておいて。提案の結論を出したい」と頼んだとします。PA が目指すのは、会議と未決の事項を結び付け、会議前に役立つ情報を準備することです。会議後に自分がメモを渡したら、引き受けた後続作業と単なる提案を区別し、残る仕事を引き継ぎ、外部に何かを送る前には尋ねます。**これは製品の方向性を示す例であり、観測済みの動作や現在の Homebrew 版の対応機能ではありません。**

そのためには、長い会話履歴だけでは足りません。メタデータは会議の日時・場所・参加者を記録します。**オントロジー**は、会議と人・目標・決定・約束との関係を表します。招待を受けただけで約束が成立するわけではありません。予定の視点では時間を調整し、プロジェクトの視点では決定を追いますが、どちらも出典のある同じ会議を参照します。進行中の仕事には未完了のことを残し、権限は PA ができることを制限し、根拠は実際に起きたことを示します。

この区別は会議以外にも当てはまります。出典のある株式の保有情報を、資産管理の視点では財務全体との関係で見ます。投資一任の視点では、明示された委任の範囲と制約を先に確かめます。役割の名前やもっともらしい推論だけで、売買の権限は生まれません。

AgentOS は、事実、役割ごとの解釈、任せた仕事、実際の権限と実行の根拠を、本人が管理する構造で結び付けようとしています。仕事が中断したり AI が替わったりしても、次にすべきことを見つけ直せるようにするためです。これらは設計上の例であり、提供済みの資産管理・投資一任サービスや観測済みの実行ではありません。状況の変化に先回りして注意を向けることは、現在の反応型 Presence を超える今後の方向であり、現時点で常時監視ができるという主張ではありません。

## 日常の短い言葉にも、同じ PA

*製品の方向性を説明する例であり、実際に観測した動作や提供済みの購入機能ではありません。*

下の図は、PA との会話を三つの場面にまとめたものです。位置を共有して帰り道の夕食を探す場面、ゴルフベルトを比較してカート操作前にアカウントへのログインを求める場面、レストランの写真から近くの散歩へ話が続く場面を示します。説明用に編集した再構成画像であり、製品画面そのものの撮影や連携機能の提供実績ではありません。

[日本語画像をフルサイズで見る](docs/assets/readme/owner-pilot-conversation.ja.png) · [元の参考画像を見る](docs/assets/readme/owner-pilot-conversation-reference.jpg)。

画像内の会話は、次の内容です。

1. **帰り道の夕食：**「帰りに夕食を食べようかな」。PA は現在地を尋ね、距離と営業状況を示した三つの店を提案します。オーナーは二番目を選びます。
2. **このベルトを探して：** オーナーが写真を送り、PA が三つのベルトを比較します。一番目をカートに入れてほしいと頼むと、PA は操作を進める前に買い物用アカウントへのログインを求めます。
3. **ここで夕食中。その後は？：** レストランの写真を送り、食後の過ごし方を尋ねます。PA は近くの散歩道、カフェ、バーを提案します。散歩を選ぶと、道順と営業時間を確かめると答えます。

数時間あいて交わす短い言葉にも、同じ継続性が必要です。

> 「コーヒー、もうなくなりそう。」<br>
> 数時間後：「今から出るんだけど、途中で買えるところあるかな？」<br>
> その後：「時間ないな。前と同じものを買っておいて。」

目指す姿はシンプルです。PA が何を買う話なのか、「前と同じもの」が何なのかを引き継いで理解し、関連する文脈を使い、足りない情報や権限は必要になった時に尋ねます。自分は話を続ければよく、作業の手順を組み立てる必要はありません。

## まずは試してみる

以前のプレビュー版で、自分のモデルと会話を始められます。上の会議の場面をそのまま再現できるわけではありません。

macOS で [Homebrew](https://brew.sh) を使う場合：

```sh
brew install jongtae/agentos/agentos
agentos start
```

1. ブラウザーで [http://127.0.0.1:8787](http://127.0.0.1:8787/) の設定画面が開いたら、**바로 시작하기**（今すぐ始める）を選びます。
2. 自分のモデルを接続し、接続テストを完了します。ツール呼び出しに対応したローカルの Ollama モデル、または自分の API 利用権限で OpenAI、OpenAI 互換サービス、Anthropic を使えます。設定画面は現在韓国語です。
3. **설정 → 외부 연결**（設定 → 外部接続）で、BotFather で作った自分のボットのトークンを入力して接続します。表示されたペアリングリンクを Telegram で開き、**開始**を押します。
4. その Telegram のチャットで、**「今週中に提案書の草案を仕上げたい。次にやることをいくつかの段階に整理して。」** と話しかけてみてください。

Python は Homebrew が一緒にインストールします。モデルの利用環境は別途用意してください。会話中は `agentos start` を実行したままにします。モデルの設定、ファイル作業、Telegram、最新ソースからの実行手順は [QUICKSTART](QUICKSTART.md) にあります。

**現在の段階：** Homebrew で入るのは以前のプレビュー版 **v1.1.0**（2026-09-23）です。その後の `main` の Presence 実装は、このリリースには含まれていません。このリリースでは予定の作成は利用できず、調査は一部対応です。詳しい範囲は[リリース内容](docs/release-manifest.json)を参照してください。[現在の状態](docs/product-status.en.md)では、利用できるもの、検証済みのもの、今後の目標を分けて説明しています。
