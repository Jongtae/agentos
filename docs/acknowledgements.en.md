# Acknowledgements and references

Personal AgentOS was shaped by other people's writing, projects, research and standards. This page credits them in one place and points to where each one is used in this repository.

Being listed here does not mean affiliation, endorsement, partnership, co-development or compatibility. Unless a line says otherwise, no code, assets or templates from these works are included in Personal AgentOS.

## Inspirations

- **Anshad Ameenza, "The Agent OS: How a Personal AI Agent Actually Works"** (2026-06-28): <https://anshadameenza.com/blog/technology/the-agent-os-how-personal-agents-work>
  - A personal agent explained as an operating system rather than a mind. Its parts are a kernel gateway, a reasoning loop, memory, installable skills, tools as system calls, a scheduler heartbeat and a swappable model.
  - Two ideas stayed with this project: "presence, not intelligence" (always reachable through the owner's own channel, with memory and a continuing loop), and treating the "lethal trifecta" of private data, internet reach and autonomous action as the security boundary to design around.
  - Used in: [Presence research](research/presence-and-settings-ux.ko.md), the [Presence Experience Contract](presence-experience-contract.en.md), and the owner-model and Attention work ([Secretary Agency Contract](secretary-agency-contract.en.md)).
- **b3os, [b3rys/b3rys-team-os](https://github.com/b3rys/b3rys-team-os)** (Apache-2.0)
  - Operating principles for agent teams: explicitly registered roles and responsibilities, runtimes kept separate from operational ownership, tracked ownership, verification and reporting of work, messages between agents treated as untrusted input, and loop and duplicate-run prevention.
  - Used in: [b3os design reference](b3os-design-reference.ko.md), which covers the extension, manifest and interoperability direction. No b3os code is included; that document records the reviewed revision and the licence obligations that would apply if code were ever included.

## Research used in design decisions

Collected in the [2026-09-28 owner-model and decision-journal review](research/owner-model-and-decision-journal-2026-09-28.ko.md), which covers the owner model (#794/#804/#805) and the decision journal:

- **Agent memory**
  - MemGPT/Letta (Packer et al., 2023): memory blocks and consolidation between conversations.
  - Generative Agents (Park et al., 2023): a memory stream with reflection triggered by importance.
  - Mem0 (2025): an extract/update pipeline with a history table.
  - Zep/Graphiti (2025): bitemporal facts that are invalidated, not deleted.
  - LangMem, A-MEM, CoALA (Sumers et al., 2023): memory taxonomy and the decision cycle.
  - LongMemEval (ICLR 2025): knowledge-update, temporal-reasoning and abstention tests.
- **Explaining and inspecting beliefs**
  - Judy Kay's scrutable user models: see the belief, its evidence and its meaning, and change it.
  - Chan et al., "Visibility into AI Agents" (FAccT 2024): identifiers and activity logs.
  - Research showing that chain-of-thought is not a faithful explanation, so audit records keep observed decisions, inputs and evidence instead of hidden reasoning.
- **Agent loop and safety vocabulary**
  - ReAct (Yao et al., 2022).
  - Simon Willison's "lethal trifecta".
- **Presence and interaction**: the sources listed in the [Presence research](research/presence-and-settings-ux.ko.md).

## Standards and protocols

- **Model Context Protocol (MCP)**: how the owner's CLI worker reaches AgentOS tools.
- **W3C PROV**: vocabulary for where a belief came from (generated by a Work, derived from sources, invalidated by a correction).
- **OpenTelemetry GenAI semantic conventions** and **MLflow Tracing assessments**: reference shapes for an optional decision-trace export and for recording judgments.
- **SQL:2011 temporal concepts**: valid time and system time for beliefs.

## Product patterns observed

- **Meta Muse** (observed 2026-09-28): conversational onboarding that asks for the user's name and explains what the agent can do. Noted as a direction for first-run onboarding in [#814](https://github.com/Jongtae/agentos/issues/814).
