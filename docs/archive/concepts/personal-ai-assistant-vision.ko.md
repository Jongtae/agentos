# 개인 AI 비서 비전

> **과거 참고용 한국어 번역본.** 내부 개발 기준은 [영어 원본](personal-ai-assistant-vision.en.md)을 따른다.

## 목적과 상태

이 문서는 AgentOS의 장기 북극성이다. 현재 출시되었거나 실제 검증된 기능 목록이 아니며, 지원 여부는 [현재 로드맵](../../roadmap.md)과 이름이 지정된 acceptance evidence로만 판단한다.

## 정체성

AgentOS는 범용 대화 플랫폼이나 조직이 관리하는 Agent 플랫폼의 대체재가 아니다. 한 사람이 자신의 기억, 연결한 맥락, 권한, 승인, 작업 증거를 소유한 채 여러 AI 실행자와 도구를 이용하도록 하는 개인 AI 비서 control plane이다.

사용자는 연결 절차가 아니라 원하는 결과를 말한다. AgentOS는 승인된 능력만 조율해 하나의 책임 있는 개인 비서처럼 응답한다.

## 기본 경험

신규 사용자는 **내 파일·폴더 + 내 비서**로 시작한다. 사용자가 자료를 맡기면 AgentOS는 원본을 보존하고, 대화·작업에서 찾아 활용하며, 이후 대화가 다시 쓸 수 있는 일반 파일로 결과를 저장한다. 이미 아는 자료를 반복 선택하게 하는 파일 탐색기를 만들지 않으며, 전체 대화나 모델 내부 추론을 자동 장기 기억으로 만들지 않는다.

2nd brain, MCP, A2A Agent, 전문 runtime은 온보딩에서 선택하게 하지 않는다. 실제 작업에 도움이 될 때만 AgentOS가 연결을 제안하고, 세부 설정은 고급 관리 화면에 둔다.

## 자료와 저장 모델

파일과 폴더가 기본 자료 시스템이다. 연결한 참고 폴더는 기본 읽기 전용이며 승인된 범위에서 검색·읽기할 수 있고, AgentOS 관리 작업공간은 소유자가 허용한 범위 안에서만 새 자료와 결과물을 쓴다. 사용자가 선택한 일반 동기화 앱은 파일을 동기화할 수 있지만 AgentOS는 동기화 엔진이나 중앙 인증 서비스를 추가하지 않는다.

AgentOS는 원본과 추출 텍스트·전사·요약, 초안, 확정 기록을 구별한다. 사용자 자료와 재생성 가능한 검색 인덱스를 분리하고, 인덱스와 영속 작업·승인·근거·복구·인증 상태도 분리한다. 원본을 Markdown 기록이나 요약으로 대체하지 않는다. 사용자 수정·이름 변경·삭제는 오래된 결과를 안전하게 처리해야 하며 원본을 몰래 되살리거나 수정하면 안 된다.

## 연결 모델

| 종류 | 역할 | AgentOS의 책임 |
| --- | --- | --- |
| MCP | 외부 데이터와 도구 | 권한, 데이터 공유, 호출 승인, 근거 |
| A2A | 독립 전문 Agent에 작업 위임 | 입력 범위, 작업 상태, 취소, artifact 검증 |
| Runtime | 격리된 로컬 또는 구독형 실행자 | 실행 경계, 도구 allowlist, 시간·비용 한도 |

연결은 활성화, 일시 중지, 해제할 수 있다. 활성화는 비서가 해당 capability를 고려할 수 있다는 뜻일 뿐, 민감 데이터 전달이나 외부 쓰기 행동을 자동 허용하지 않는다.

## 소유권과 행동 원칙

- 개인 기억, 승인 이력, 작업 상태, 실행 근거는 owner-controlled runtime에 남는다.
- 외부 엔진에는 작업에 필요한 승인된 최소 맥락만 전달한다.
- 읽기와 조사는 정책 범위에서 처리할 수 있지만, 외부 전송, 파일 수정, 계정 변경, 결제처럼 결과가 남는 행동은 명시 승인을 요구한다.
- 연결 해제는 해당 연결의 비밀값과 설정을 제거하되, 소유자의 작업 증거와 결과를 지우지 않는다.
- 실패한 작업은 실행되지 않은 일을 완료했다고 말하지 않으며, 취소·재시도·복구 가능한 상태를 남긴다.
- 폴더 grant는 홈 디렉터리 접근, 임의 셸 실행, 원본 덮어쓰기·삭제, 대량 이동, 외부 전송 권한이 아니다.
- 외부 AI·메신저·에이전트·수신자 전송은 로컬 저장과 다른 정책·승인 경계다.

## 선택 connector와 위임

Google Drive 같은 서비스 connector는 선택한 자료를 가져오거나 서비스 고유 작업을 자체 경계 안에서 수행하는 선택 기능이다. 필수 저장 기반이 아니다. 제품 안내·정책 사이트도 OAuth/token/자료 중계가 아니며 로컬 파일 작업의 선행조건이 아니다. 사람 또는 다른 agent에게 자료 묶음을 위임하고 결과를 회수하는 기능은 명시 경계를 갖는 미래 capability다.

## 향후 capability acquisition

장기적으로 AgentOS는 사용자의 요청을 처리할 수 있는 검토된 Agent나 capability를 카탈로그에서 찾아 제안할 수 있다. 그러나 Agent가 스스로 설치·활성화·권한 상승을 완료하는 것은 기본 행동이 아니다.

이 방향은 MP1 이후 별도 Master Plan에서만 검토한다. 최소한 출처와 고정 버전, 라이선스, 요청 권한과 데이터 범위, 격리 방식, 비용, 제거·복구 방법, health check를 설치 계획으로 먼저 보여 주고 소유자의 명시 승인을 받아야 한다. 설치된 capability는 처음에 비활성 상태이며, 실행 evidence가 생기기 전에는 실제로 동작한다고 주장하지 않는다.

## 비목표와 증명 방식

MP1은 공개 marketplace, 임의 코드 실행, 무제한 자동 위임, 개인 데이터를 복제하는 중앙 control plane을 범위에 넣지 않는다. 향후 capability acquisition도 검토된 카탈로그와 소유자 승인·격리·검증을 우회하지 않는다. AgentOS는 ChatGPT나 기업 Agent 플랫폼보다 보안적 우위를 일반적으로 주장하지 않는다. 대신 개인 상태와 신뢰 경계가 어디에 있는지를 투명하게 만든다.

Master Plan 개발에서 capability는 선언된 contract와 자동 테스트가 통과하기 전에는 지원된다고 주장하지 않는다. 외부 credential, OAuth client, endpoint, 활성화는 Master Plan 완료 뒤 소유자 제어 운영 모드 배포에서만 설정하며, mock 검증은 외부 연결이 live라는 주장이 아니다. 장기 실행 계획은 [Master Plan 1](../../master-plan-01-personal-assistant-core.ko.md)에서, 그 다음 선택 절차는 [Master Plan 2](../../master-plan-02-proposal.ko.md)에서 관리한다.
