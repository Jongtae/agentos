# Decision Layer — superseded orchestration history

Extracted by DOCS-CONSOLIDATE-03 (#1055) from the canonical [Decision Layer](../../../decision-layer.en.md). These clauses are preserved as design/implementation history. #826 is the current precedence for plan shape and removed the plan-selected tool subset and pinned default worker.

## Historical #710 / ORCH-01 plan and tool-subset clauses

- **The plan.** Before a Work runs, one `structured` call over the owner's request (whole), a bounded recent-conversation excerpt (the rows a CLI worker is shown: every owner/assistant row except file-workspace document jobs; #740 removed the source-label filter, pilot posture; every fact still passes the existing judgment redaction, which removes stored secrets, credential shapes and the current Work's saved private values, while earlier rows are the same text a CLI worker is shown and are not re-scrubbed with their own Works' saved values), the owner profile and current-context snapshot text (redacted, bounded; #804), the names and sizes of the selectable context sections, the catalogue, the Work budget and any earlier attempts returns `{worker, model, brief: {goal, context, completion_criteria}, tools_mode, tools, reason}`. The question asks the brief to resolve what a follow-up refers to from that conversation, only when the request refers to or continues it (a new request is its own topic), and not to brief the worker to ask the owner for what the conversation already says (#740, #804). Deterministic code **only validates**: the worker is offered and available, the model is `""` (the worker's default) or listed for it, the context sections are declared names, the tools are a subset of that worker's tools, and the Work budget still allows an attempt (`MIN_ATTEMPT_SECONDS`). The brief reaches the worker as its own turn-context section (`agent_runtime.BRIEF_HEADING`) before the owner's request, which stays verbatim and takes precedence; unselected sections are not sent, except the profile and current context, which every attempt carries (#804; `orchestrator.ALWAYS_SECTIONS`). A Work that carries spliced private material (documents, Drive, context inbox, notes) or an attachment approved for the default destination is **pinned**: only the default worker is offered.
- **Tools per request.** A subset narrows `Capabilities.allowed_tools`, the bridge's list (`--only`) and Claude Code's `--allowedTools`; it can never widen them. The existing invariant is kept: a private-read tool and the CLI's own web search are never on in the same turn. A selected private-read tool turns the CLI's own search off for that attempt (`orchestrated_private_tools`), a subset without `web_search` turns it off (`orchestrated_no_search`), and on a native-search turn private reads stay withheld as before (#678/#701). This is how a natural-language notes request on a native-search route can read notes (the #711 gap) without a request-specific rule.

- **ORCH-02 (#729): full toolset by default, learning from failed attempts.**
  - `tools_mode` defaults to `worker_default` (the worker's full offered toolset). A `subset` is valid only with a stated `tools_reason` (recorded in the `planned` event); without one the plan is invalid. The plan call carries one declared line per tool (`tool_descriptions`: the first sentence of the host action's own model-facing description, not text written for the planner).
  - The next plan call reads a factual summary of each earlier attempt: the tools called, those that failed (with their code) or started and never completed, own web searches that reported no source URL, the evaluation and its reason, and the answer excerpt labelled model-stated. Validation refuses a worker + effective model + effective tool set that already fell short (`invalid: repeat`).

- **ORCH-03 (#735): guardrails from Work a8e6aa7b.**
  - **Tool subset rule (validation, not a judgment).** A planned subset stands only when it removes the whole private-read category, or the whole web-search category (`web_search`, `bounded_public_research`, the set a worker's own search replaces), of the worker's offered tools, to keep the two apart, removes nothing else and states a `tools_reason`; removing part of a category is not a separation. Every other subset (for example a single tool) becomes the worker's full offered toolset; the `planned` event records `tools_replaced: {requested, why}` (`shape`, `no_reason` or `not_offered`).
  - **Runnable models only.** A Codex worker offers only the models the installed binary bundles and lists (`DecisionRoutes.bundled_models`: `codex debug models --bundled` with an empty per-call `CODEX_HOME`, cached per binary fingerprint, a failed listing included; never the plain `codex debug models`); without a listing it offers only its default. A model is remembered as refused only on the CLI's own unsupported-model signal, classified at the execution boundary (`bounded_execution.unsupported_model`: Codex's `The '<model>' model is not supported` message, Claude Code's `[claude-code:unrecognized_model]` stderr tag), never on a generic rejection that mentions the model; the route and model are kept in `route_model_refusals` (no refusal text, offered again after 7 days) and dropped from later catalogues and from the rest of the same Work. When the refused model is the route's configured default, `model: ""` resolves to the next runnable model (the catalogue records `default_refused`, and the attempt runs the substitute explicitly); with no runnable model left the worker is unavailable (`default_model_refused`).
