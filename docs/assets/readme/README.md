# Public README visuals

The four public READMEs share the same information order and evidence boundaries. This directory contains repository-owned assets, not an external image feed. [The documentation map](../../README.md) remains the authority map.

- `interaction-model.{en,ko,ja,zh-CN}.svg`: illustrative Assistant → Computer agent → Personal AgentOS comparison. NASDAQ/NVIDIA and Amazon explain interaction, not shipped integrations.
- `presence.{en,ko,ja,zh-CN}.svg`: Owner ⇄ PA over AgentOS-owned Memory, Context, Work, Authority, Evidence and Events; Judgment orchestrates replaceable AI and tools/services. Architecture, not operating evidence.
- `hero.*.html` / `hero.*.png` and `scenes.*.html` / `scenes.*.png`: reconstructed and condensed v1 synthetic journey illustrations. The HTML is generated by [build_readme_visuals.py](../../../scripts/build_readme_visuals.py). These are not live-account screenshots. See [product status](../../product-status.en.md) and the [release manifest](../../release-manifest.json) for evidence and limits.

- `continuing-conversation.{en,ko,ja,zh-CN}.svg`: three moments in a representative conversation; eligible context, time/route and earlier choice are resolved beneath a continuing Work. Product direction, not a composite live run.
- Each concept figure has a `.narrow.svg` composition selected by the README’s `<picture>` below a 600-pixel viewport. All text and processing steps match its desktop version.

## Editing and visual verification

[build_concept_visuals.py](build_concept_visuals.py) is the shared, standard-library source for all 24 concept SVGs. Run `python3 docs/assets/readme/build_concept_visuals.py` after editing its localized content or layout. Keep the same processing steps, layers, time sequence and evidence boundaries in every locale and composition. The existing v1 generator remains separate.

The desktop canvas is 840 units; narrow compositions are 420 units with 17–24-unit main text. Native `<picture>` selects the narrow figure at a viewport of 600 pixels or less. GitHub displays it at approximately 309 CSS pixels in a 375-pixel viewport (254 at 320). Use explicit text rows and ordinary glyph widths; never squeeze text with `textLength` / `spacingAndGlyphs`. No external fonts, scripts or image resources are required. Adjacent Markdown retains the comparison, architecture explanation and representative transcript for accessible text and clients without picture support.

After a change:

1. Run `python3 scripts/verify_readme_localization.py` and check all README asset/link paths.
2. Open each SVG in a browser. Inspect text bounds against both its card and the viewport, including sans-serif and serif fallback. Check text against other rows as well as card bounds. Text must not overlap another row or leave its card.
3. Inspect all four rendered GitHub READMEs at normal desktop width, 375 pixels and 320 pixels. Check each image has loaded and `currentSrc` selects the expected desktop/narrow asset; inspect the comparison and architecture at their actual displayed size, then read the whole README in order. A Markdown image path or successful structural check alone is insufficient.
4. Keep the comparison before release imagery, the evidence classification before the v1 panels, and the across-time conversation explicitly illustrative. Publish no owner-pilot screenshot without selected, redacted and revision-linked source evidence.

Browser screenshots and font/layout measurements prove documentation rendering only. They do not prove live AgentOS behavior.
