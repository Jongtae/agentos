# SECRETARY-01 프로브 실행 절차 (A·B·C, 숨겨둔 D)

SEC-EVAL-01 [#660](https://github.com/Jongtae/agentos/issues/660) · 계약: [Secretary Agency Contract](../secretary-agency-contract.en.md) "Probe scenarios and the no-scenario-code rule", "Completion rule" · 감사 양식: [completion audit](secretary-01-completion-audit.en.md)

**이 문서는 실행 절차이지 증거가 아닙니다.** 증거는 소유자가 자기 설치본에서 실제로 실행한 뒤 남기는 `secretary-01-probe-<A|B|C|D>-<날짜>.json` 기록과 그 기록을 확인한 감사 항목입니다. 이 문서가 있다는 사실, 테스트 통과, 픽스처 실행은 프로브 완료가 아닙니다.

실제 모델·검색 제공자·Telegram·브라우저를 쓰는 실행은 소유자가 직접 하며 횟수를 정해 둡니다(#612). 프로브마다 한 번 실행하는 것이 기본이고, 다시 실행했다면 그 이유를 감사 문서에 적습니다.

## 0. 공통 준비 (한 번)

1. **실행 중인 코드 확인.** 설치본이 저장소 작업 사본에서 실행된다면 `git rev-parse HEAD` 값을 적어 두고, 그 커밋으로 AgentOS를 다시 시작합니다. 숨겨둔 D는 반드시 마감(closeout) 커밋에서 실행합니다.
2. **AI 연결.** 설정 › AI 연결에서 기본 AI를 **API 연결**로 둡니다. 완료 판단(`finish` + 목표 판단)은 현재 직접 API 경로에만 있습니다. 구독 CLI 경로는 아직 `finish`가 없어 프로브 증거로 쓰지 않습니다.
3. **판단 AI.** 설정 › AI 연결 › 판단 AI (대화 해석)가 "사용 안 함"이 아니어야 합니다. 판단 AI가 없으면 도구를 쓴 요청은 항상 "일부 완료(partial)"로 끝나며, 이는 계약상 의도된 동작입니다.
4. **검색 제공자 키.** 설정 › 외부 연결 › 웹 검색 제공자에서 Naver(Client ID·Client Secret)와 Brave 키를 저장합니다. 어느 제공자를 쓸지는 AI가 요청마다 고릅니다. 기본 검색 제공자 선택은 AI가 제공자를 지정하지 않았을 때만 쓰입니다.
5. **브라우저 기능 설치.** 설치본과 같은 Python 환경에서:

   ```sh
   pip install 'personal-agentos[browser]' && playwright install chromium
   ```

   배포 이름은 `personal-agentos`입니다(설정 화면의 설치 안내와 같습니다).
6. **Telegram 페어링.** 모든 프로브 요청은 페어링된 Telegram 대화에서 보냅니다.
7. **개인 정보가 들어가는 기록.** 기록 파일에는 비밀값·쿠키·브라우저 입력 문자는 들어가지 않지만, 요청 문장·검색어·답변·페이지 제목은 들어갑니다. 저장소에 올리기 전에 파일을 직접 읽어 보고, 알레르기·장소 같은 개인 정보가 공개되면 안 된다면 `--omit-text`로 다시 만듭니다(구조·제공자·선택지는 남고 자유 문장은 길이와 해시로 바뀝니다).

## 1. 증거 기록 방법 (모든 프로브 공통)

1. 요청을 보낸 뒤 Telegram 최종 답변을 받을 때까지 기다립니다.
2. 웹의 **작업 현황**에서 해당 요청을 펼치고 **기술 정보 › 작업 ID**를 복사합니다.
3. 저장소 작업 사본에서 실행합니다(AgentOS를 멈출 필요는 없습니다. 읽기만 합니다).

   ```sh
   python3 scripts/prepare_owner_smoke.py record-probe \
     --data "<AgentOS 데이터 폴더>" --work <작업 ID> --probe A --head "$(git rev-parse HEAD)"
   ```

   - `--data`를 생략하면 `AGENTOS_DATA`, 없으면 `~/.local/share/agentos`를 씁니다.
   - `--work latest`는 가장 최근 작업을 고릅니다. 다른 요청이 끼어들지 않았을 때만 쓰세요.
   - 결과는 화면에 출력되고 `docs/evidence/secretary-01-probe-A-<오늘 날짜>.json`으로 저장됩니다. 같은 이름의 파일이 있으면 덮어쓰지 않고 거절합니다. `--print-only`는 저장하지 않습니다.
4. 기록에서 다음을 확인하고 감사 문서의 해당 행에 적습니다.
   - `work.id` — 작업 ID
   - `tool_calls[].call_id`, `provider`, `host_action`, `alternative` — 어떤 경로를 어떤 순서로 시도했는지
   - `finish.evidence_refs`와 `finish.cited` — 완료 주장이 가리킨 관찰 결과
   - `goal_judgment` — `yes` / `no` / `unavailable`
   - `final_outcome` — `succeeded` / `partial` / `failed` / `unknown`
   - `report` — 답변(`reply`), 확인된 부분(`observed`), 진행하지 못한 점·확인하지 못한 부분·다음 단계
   - `checks` — `succeeded_iff_judged_done_claim`이 `true`인지, 반복 경로 거절 수
5. **답변이 관찰과 맞는지**는 소유자가 직접 확인합니다. 기록은 AgentOS가 관찰한 것만 보여 줍니다. 예를 들어 "장바구니에 담았습니다"라는 답변이라면 실제 장바구니에 그 책이 있는지 소유자가 봅니다.

## 2. 프로브 A — 책을 교보문고 장바구니에

**준비**

- 공통 준비 1–6.
- **교보문고 로그인 한 번.** 설정 › 외부 연결 › 브라우저 로그인 세션 › 로그인할 사이트 주소에 교보문고 주소를 넣고 **브라우저 열어 로그인**을 누릅니다. 열린 창에서 직접 로그인한 뒤 창을 닫습니다. AgentOS는 비밀번호를 보거나 입력하지 않습니다.
- **선호 서점(선택).** 설정 › 개인정보 · 진단 › 프로필에 선호 서점을 저장해 두거나 대화에서 말해 둡니다. 이것은 소유자 데이터이지 코드가 아닙니다.
- 결제 수단은 연결하지 않습니다. 결제는 이 프로브의 범위가 아닙니다.

**Telegram에 보낼 메시지**

> 《리더는 언제 차이를 만들어내는가》 사서 볼 수 있게 장바구니에 넣어둬

**성공으로 보는 모습**

- Telegram 최종 답변: 장바구니에 담았다고 말하고, 어떤 책(제목·저자·판)인지 밝힙니다. "일부 단계만 완료했습니다"로 시작하지 않습니다.
- 작업 현황: 상태 **완료**. 처리 과정에 웹 검색(제공자 표시), 브라우저 페이지 열기, 브라우저에서 누르기가 보이고, 마지막으로 장바구니 페이지를 연 단계가 있습니다.
- 기록: `final_outcome: succeeded`, `goal_judgment: yes`, `finish.cited`에 장바구니 페이지 URL이 있는 브라우저 단계가 포함됩니다.
- 소유자 확인: 교보문고 장바구니에 그 책이 실제로 있습니다.

**성공이 아니지만 정직한 결과**

- 로그인 만료: 답변이 로그인이 필요하다고 말하고, 할 수 있는 부분(책 찾기)은 보고합니다. 다시 로그인한 뒤 새로 요청합니다.
- 찾지 못함: 답변이 시도한 경로(다른 제공자, 바꾼 검색어, 사이트 자체 검색)를 말하고 다음 단계를 제안합니다. 기록의 `alternative`가 비어 있지 않아야 합니다.

**적어 둘 id**: 작업 ID, 검색 호출 id와 제공자, 상품 페이지를 연 호출 id, 장바구니 담기 호출 id, 장바구니 페이지를 확인한 호출 id(`finish.cited`), 소유자의 장바구니 확인 결과(예/아니오).

## 3. 프로브 B — 내일 일정 미리 알림

**선행 조건**: 알림을 저장하고 보내는 Attention 준비 기능 SEC-ATTN-01 [#659](https://github.com/Jongtae/agentos/issues/659)가 병합된 뒤에 실행합니다. 그 전에는 일정 읽기까지만 확인할 수 있고 프로브 B는 완료로 기록하지 않습니다.

**준비**

- 공통 준비 1–3, 6.
- 설정 › 외부 연결 › Google 연결에서 **Google Calendar**를 연결합니다(읽기).
- 내일 시각이 정해진 일정이 캘린더에 하나 이상 있어야 합니다. 시작 시각을 적어 둡니다.
- 설정 › 개인정보 · 진단 › 현재 맥락 사용을 켜 두면 시간대와 현재 상황이 요청에 들어갑니다.

**Telegram에 보낼 메시지**

> 내일 일정 보고 미리 알려줘

**성공으로 보는 모습**

- Telegram 최종 답변: 내일 일정(제목·시각)을 캘린더에서 읽은 대로 말하고, 언제 알림을 보낼지 밝힙니다.
- 알림이 #659가 정한 저장소에 의도한 시각으로 들어 있습니다(작업 현황 또는 #659가 보여 주는 화면에서 확인).
- 일정 시작 전에 Telegram으로 알림이 실제로 도착합니다. 도착 시각을 적습니다.
- 기록: 요청 작업은 `goal_judgment: yes`, `final_outcome: succeeded`이고 `finish.cited`에 캘린더 조회와 알림 저장 단계가 있습니다.

**적어 둘 id**: 요청 작업 ID, 캘린더 조회 호출 id, 알림(준비) id와 예정 시각, 알림 전달 시각과 일정 시작 시각. 전달이 별도 작업으로 기록된다면 그 작업도 `--print-only`로 출력해 id를 감사 문서에 적습니다(같은 날짜의 B 기록 파일은 하나만 저장됩니다).

## 4. 프로브 C — 알레르기·취향·위치를 반영한 점심 제안

**준비**

- 공통 준비 1–4, 6.
- 설정 › 개인정보 · 진단 › 프로필에 알레르기, 음식 취향, 자주 있는 장소(예: 회사)를 저장합니다. 대화에서 "나 ○○ 알레르기 있어"처럼 말해 저장해도 됩니다.
- 설정 › 개인정보 · 진단 › **현재 맥락 사용**을 켭니다.
- Telegram에서 현재 위치를 공유합니다(첨부 › 위치, 또는 실시간 위치 공유). 실시간 위치는 15분 안의 것만 쓰입니다. 공유하지 않으면 저장된 장소를 씁니다.
- "준비된 제안이 제때 있는지"(Attention 준비)는 #659 병합 뒤에 확인합니다. 그 전에는 요청에 대한 답변 부분만 확인할 수 있습니다.

**Telegram에 보낼 메시지**

> 점심 뭐 먹지?

**성공으로 보는 모습**

- Telegram 최종 답변: 알레르기 음식을 피하고 취향에 맞는 근처 식당이나 메뉴를 제안하고, 현재 출처(조회 출처 목록)를 붙입니다.
- 작업 현황: 상태 **완료**. 처리 과정에 웹 검색(AI가 고른 제공자)과 필요하면 페이지 읽기가 보입니다.
- 기록: `goal_judgment: yes`, `final_outcome: succeeded`, `finish.cited`의 검색 결과에 출처 URL이 있습니다.
- 소유자 확인: 제안에 알레르기 음식이 없고, 거리와 영업 정보가 실제와 맞습니다.
- (#659 병합 뒤) 준비된 점심 제안이 예상 시각 전에 준비되어 있습니다.

**적어 둘 id**: 작업 ID, 검색 호출 id와 제공자·locale, 페이지 읽기 호출 id, 위치 출처(`location_source.ref`가 있으면), 준비 id(#659 뒤), 소유자의 알레르기·거리 확인 결과.

## 5. 숨겨둔 프로브 D — 마감 시점에 소유자가 고름

- **언제**: 마감 커밋이 정해진 뒤, 그 커밋으로 설치본을 다시 시작하고 실행합니다.
- **무엇을**: 개발 중에 한 번도 쓰지 않은 새 일상 요청 하나입니다. 이슈, PR, 테스트, 문서, 에이전트와의 대화 어디에도 미리 적지 않습니다. 실행 직전에 소유자가 정하고, 실행한 뒤에만 기록합니다.
- **예시(그대로 쓰지 마세요. 이런 종류라는 뜻입니다)**: 주말에 들를 동네 꽃집이나 빵집 찾기, 다음 주 약속 전에 챙길 것 정리, 자주 사는 생필품을 다른 쇼핑몰에서 찾아 비교하기, 지난달에 본 기사 다시 찾기. 이 문서에 적힌 예시는 개발 중에 노출된 것이므로 D로 고르지 않습니다.
- **기록**: `--probe D`로 같은 방법으로 기록하고, 감사 문서에 요청 문장(또는 `--omit-text` 해시)과 실행 커밋을 적습니다.
- **판정**: D가 실패했을 때 그 이유가 **특정 사이트·제공자·요청 종류를 코드에 넣어야만 고칠 수 있는 것**이라면 프로그램 완료는 거절됩니다. 일반 기능이 모자란 경우(예: 아직 없는 도구)라면 그 사실을 기록하고 소유자가 판단합니다.

## 6. 하지 않는 것

- 프롬프트, 설정, 코드에 프로브의 사이트·제공자·요청을 적어 넣어 통과시키지 않습니다. 선호 서점 같은 소유자 프로필은 괜찮습니다.
- 결제, 주문 확정, 카드 입력은 하지 않습니다. 이런 단계에서 AgentOS는 승인을 요구하며, 승인하지 않습니다.
- 브라우저 로그인 창에 AgentOS가 비밀번호를 넣게 하지 않습니다. 로그인은 소유자가 직접 합니다.
- 기록 파일을 손으로 고치지 않습니다. 잘못 기록했다면 새로 기록하고 이유를 감사 문서에 적습니다.
