# UX-06 — Telegram 대화 말풍선 기준

> 2026-10-01 (#958): 아래의 상태 카드(`요청을 받았습니다. 곧 시작할게요.`, `진행 보기`, `작업 취소`)는 더 이상 보내지 않는다. 대기 중인 요청은 소유자 메시지의 👀 반응만 보이고, 실행 중에는 `typing…`과 중지 가능한 초안만 보인다. 취소는 말로 하거나 Telegram의 중지 버튼으로 한다. 카드 관련 문장은 이전 범위의 기록이다.

AgentOS의 Telegram은 설정용 봇이나 작업 로그가 아니라, 소유자가 일상적인
자연어로 개인 에이전트에게 일을 맡기는 대화창이다. Telegram 클라이언트의
말풍선 자체를 바꾸지는 못하지만, AgentOS가 보내는 문장·순서·버튼은 하나의
일관된 대화 경험이어야 한다.

## 사용자 흐름

### 1. 일반 요청

1. 소유자가 자연어 요청을 보낸다.
2. AgentOS는 요청 내용이나 내부 ID를 되풀이하지 않는 상태 카드 하나를 보낸다.
   - 대기: `요청을 받았습니다. 곧 시작할게요.`
   - 처리 중: 같은 카드를 수정해 `요청을 처리하고 있어요.`로 바꾼다.
3. 처리가 끝나면 같은 카드를 `처리가 끝났습니다.`로 수정한다.
4. 결과는 **답변 말풍선 하나**로 보낸다. “작업이 완료되었습니다” 같은
   별도 완료 알림을 같은 결과와 함께 추가로 보내지 않는다.
5. 길어서 한 말풍선에 담기 어려운 결과는 첫 말풍선에 읽을 수 있는 앞부분과
   `전체 결과는 AgentOS 웹에서 확인하세요.`를 표시한다. 이 첫 구현에서는
   결과 내용을 Telegram에 다시 중복 전송하는 상세 버튼을 만들지 않는다.

### 2. 승인 필요

문서 또는 개인 컨텍스트를 외부 모델에 전달해야 할 때는 결과 말풍선 대신 승인
말풍선을 보낸다. 이 말풍선은 필요한 행동과 경계만 설명하며, 문서·컨텍스트·요청
원문·토큰·내부 식별자를 보여 주지 않는다. 승인 결과는 같은 승인 말풍선을
수정해 한 번만 알린다.

### 3. 취소·실패·재시작

- 대기 상태 카드에서만 `작업 취소`를 제공한다. 취소하면 같은 카드를
  `이 요청은 취소됨 상태입니다.`로 수정하고 결과 말풍선은 보내지 않는다.
- 실패하면 상태 카드를 실패로 수정하고, 이유를 과장하지 않는 한 개의 결과
  말풍선을 보낸다.
- 재시작으로 중단되었거나 Telegram 전송 여부가 불명확하면 성공으로 보이지
  않는다. 카드와 `진행 보기`는 웹 기록을 확인하거나 새 요청을 시작하라는
  안전한 다음 행동만 안내한다.

## 화면 기준

| 종류 | 목적 | 말풍선 규칙 | 버튼 |
| --- | --- | --- | --- |
| 상태 카드 | 요청이 접수·진행·종료됐음을 보임 | 요청 본문·도구명·ID를 넣지 않음, 같은 카드만 수정 | 대기/진행: 진행 보기, 대기: 작업 취소 |
| 결과 | 실제 답변을 읽음 | 요청당 한 번, 평문 우선, 긴 결과는 안전하게 축약 | 없음 |
| 승인 | 외부 공유 전에 선택하게 함 | 공유 대상과 선택 결과만 표현, 내용은 숨김 | 승인 / 허용 안 함 |
| 복구 | 불확실성을 숨기지 않음 | 자동 재시도·전송 성공을 주장하지 않음 | 진행 보기 |

문장에는 장식용 이모지를 기본으로 넣지 않는다. 상태가 다르다는 것은 문장과
버튼 변화로 충분히 구분한다. 최종 결과는 Telegram 기본 말풍선으로 전달되고,
상태 카드는 제어와 신뢰 회복에만 사용한다.

## 구현 범위

UX-06 첫 구현은 다음을 바꾼다.

- 성공·실패 작업의 중복된 완료 알림을 없애고, 실제 결과 전송을 유일한
  터미널 답변으로 만든다.
- 카드의 상태 전환과 결과 전송 순서를 테스트로 고정한다.
- 이미 있는 소유자·개인 채팅·세대·정확한 메시지 결합, 문서 승인 경계,
  불확실한 전송 미재시도 규칙을 유지한다.

새 채널, Telegram 클라이언트 대체, 임의의 외부 공유, 호스트 권한, 결과 전문의
추가 저장은 범위에 포함하지 않는다.

## 검증 기준

자동화 테스트는 다음을 확인한다.

- 정상 작업: 상태 카드 생성·수정, 결과 말풍선 한 번, 완료 알림 중복 없음.
- 실패 작업: 상태 카드 수정과 실패 결과 말풍선 한 번.
- 승인·취소·재시작·불확실 전송의 기존 안전 경계가 유지됨.
- 결과와 카드에 요청 원문·문서·토큰·내부 ID가 새로 노출되지 않음.

실제 모바일 Telegram 검증은 자동화 테스트와 구분한다. 소유자가 일반 요청,
긴 결과, 승인, 취소, 재시작 뒤의 흐름을 확인하되 메시지 본문이나 비밀값을
GitHub에 기록하지 않는다.

## 완료 검증

- 자동화: Personal AgentOS 루트 테스트 140개 통과.
- 실행: 기존 개인 데이터로 실행 중인 UX-06 런타임의 loopback health check 통과.
- 실제 화면: Telegram Desktop에서 상태 카드가 완료 상태로 수정된 뒤 실제 답변 말풍선 하나가 이어지는 것을 관찰했다. 같은 요청에 대한 일반 완료 알림은 보이지 않았다. 메시지 내용·계정 식별자·토큰은 기록하지 않는다.
