# 로컬 웹의 역할과 Codex 작업 인계

2026-09-20 소유자 결정. 결정 기록 #379 / PR #380. 구현 이슈 #382 (WEB-ADMIN-01).
영문 기준: [Local Web Management Contract](web-management-contract.en.md).

## 확정한 방향

**Telegram은 비서에게 일을 부탁하고 답을 받는 곳이고, 로컬 웹은 AgentOS를 관리하는 유틸리티입니다.** 웹에 별도의 일반 채팅창이나 Telegram 전체 대화를 기본 화면으로 복제하지 않습니다.

AgentOS가 작업·기억·결과·권한·이력을 계속 소유합니다. Telegram은 현재 사용하는 대화 채널일 뿐, 제품의 상태를 소유하는 중심 시스템으로 바뀌지 않습니다. 웹 대화 표시를 없애도 기존 이력과 채팅 API, Telegram 송수신을 삭제하거나 중단하지 않습니다.

## 화면 구조

주 메뉴는 **작업 현황 / 설정**입니다 (2026-09-24 소유자 결정, #562로 변경). 예전의 **내 기록** 메뉴와 모든 기록 유형을 둘러보는 검색 화면은 없앴습니다. 저장된 항목 하나는 그 항목을 남긴 대화 턴이나, 그 유형을 관리하는 설정 화면(기억·메모·승인 대기 기억 후보는 개인정보 · 진단, 프로젝트와 저장된 결과는 파일 · 저장)에서 `#item/<유형>/<id>` 링크로 엽니다. 어떤 항목을 링크할지는 그 작업에 붙은 기록된 데이터로만 정하며, 답변 문구나 키워드로 추측하지 않습니다. 화면을 없애도 저장된 데이터는 지우거나 옮기지 않습니다. 설정에는 **AI 연결 / 파일 · 저장 / 외부 연결 / 개인정보 · 진단**이 있습니다. 메뉴 선택은 본문을 전환합니다. 대화 아래에 화면을 계속 붙이거나 같은 메뉴를 두 번 표시하지 않습니다.

프로젝트는 작업·기록을 묶는 선택 기능으로 남기되, 상시 최상위 메뉴나 필수 시작 단계로 강요하지 않습니다. 기존 프로젝트 데이터와 접근 경로는 보존합니다. 에이전트 설치 화면은 실제 기능이 준비됐을 때 별도로 구현합니다.

## 화면마다 필요한 것

- **작업 현황:** 의미 있는 요청의 목록 → 결과 또는 필요한 행동 → 실제 처리 과정 → 실행 상세. 완료 답변은 읽을 수 있어야 하고, 결과 파일은 실제 열기 동작으로 연결합니다. 원래 요청은 해당 작업 안에서 필요할 때 펼칩니다. 연결 명령과 내부 점검은 일반 작업과 구분하되 삭제하지 않습니다.
- **저장된 항목 하나:** 그 항목만 보여 줍니다. 메모, 기억, 임시 자료, 결과물의 내부 타입은 유지하며 삭제·승인 같은 조작도 타입에 맞춥니다. 기억 후보는 승인하기 전까지 기억으로 표시하지 않습니다.
- **설정:** 현재 연결과 바꿀 수 있는 항목을 먼저 보여줍니다. 이미 연결된 Telegram에는 빈 토큰 폼 대신 연결 상태와 관리 버튼을 보여줍니다. 실제 실행 우선순위를 표시합니다. 확인한 현재 구현에서는 구독 CLI 선택이 웹·Telegram AI 요청 모두에 우선하며, 직접 API를 설정하거나 테스트해도 선택이 바뀌지 않습니다. API 미설정만으로 전체 AI가 미연결이라고 표시하지 않습니다. 향후 실제로 경로별 연결이 다르면 각각 구분합니다.

참고 폴더는 읽을 곳, 결과 저장 폴더는 생성 파일을 쓸 곳, 프로젝트는 대화·결과를 묶는 단위입니다. 기존 폴더 설정과 권한을 설명 없이 합치지 않습니다.

## 안내와 상호작용

배너·로봇·추천 모델 카드·오늘의 팁·상시 3단계 시작 안내는 사용하지 않습니다. 필요한 설명만 해당 필드나 오류 옆에 둡니다. 파일을 쓰지 않는 작업까지 폴더 설정을 요구하지 않습니다.

예: ‘새 연결을 테스트하는 동안 기존 연결은 유지됩니다.’

모델 변경은 입력한 설정 테스트 → 성공 후 적용입니다. 실패하거나 입력이 바뀌면 기존 연결을 보존하고 재검증을 요구합니다. 주기적 갱신과 화면 이동으로 입력·커서·검색 결과·확인 화면이 사라지면 안 됩니다.

설정된 연결, 로그인 확인, 실제 실행 확인, 모델 정보는 서로 다릅니다. 모르는 모델명을 만들거나 로컬 실행을 곧 로컬 모델 처리라고 표현하지 않습니다. 도구 실행 과정도 실제 기록만 표시합니다.

## Codex에서 처리할 순서

#382 하나 안에서 다음 순서로 처리합니다. 새 기획 이슈를 반복 생성하지 않습니다.

1. 현재 소스와 겹치는 작업을 확인합니다. 이슈와 두 delivery-plan 사본에 의존성이 충족된 준비 기록이 이미 있는지, 소유자가 그 준비된 목표를 명시적으로 활성화했는지 확인합니다. 준비가 없다면 이번 실행은 W0 준비·검증·정상 병합까지만 진행하고 중단합니다. 같은 준비 실행에서 W1–W3로 넘어가지 않고 별도의 소유자 활성화가 필요함을 보고합니다. 준비 기록만 추가했다고 다른 활성 작업을 바꾸거나 구현·heartbeat를 시작하지 않습니다.
2. 준비와 명시적 활성화가 모두 확인된 뒤, 웹 대화 기본 화면을 관리 화면으로 교체하고 중복 메뉴·안내를 제거합니다.
3. 작업별 결과·상태·실행 기록을 연결합니다.
4. 기록 검색·타입별 조작·모델 상태·폴더 및 연결 안내를 정리합니다.

독립적으로 검증된 작은 변경은 먼저 PR로 병합할 수 있습니다. Telegram/API/이력 보존 테스트와 실제 브라우저 확인을 함께 수행합니다. 테스트 숫자만으로 사용성이 좋아졌다고 주장하지 않습니다. 외부 리뷰·권한만 남으면 정확한 통합 대기 기록을 남기고 같은 실패를 반복하지 않습니다. W0 또는 화면 골격만 병합해서 #382 전체를 완료 처리하지 않습니다.

## ‘Codex 작업이 이뤄질 수 있도록 조치’의 의미

**이번 조치:** 제품 결정 문서, 기존 시안의 대체 관계, 구현 이슈·수정 범위·완료 조건, 소스 계획의 준비 기록, Codex용 지침과 프롬프트를 GitHub에 남기는 일입니다.

**별개의 다음 단계:** 준비 상태를 확인하고 사용 가능한 Codex 세션에서 소유자가 #382 구현을 명시적으로 활성화하는 일입니다. 이슈 등록, 준비 기록 또는 문서 병합만으로 Codex가 자동 실행되지는 않습니다. 준비 기록이 없으면 W0까지만 처리한 뒤 중단합니다. 기존 실행 중인 세션에는 새 기준을 직접 읽도록 해야 합니다.

현재는 결정과 구현 명세를 기록한 상태입니다. 실제 화면 변경, Telegram/모델 운영 테스트, 배포가 끝났다는 뜻이 아닙니다. #381의 별도 대화 품질 계획이나 다른 후속 목표도 자동 실행하지 않습니다.

이전 utility-v1 시안의 웹 대화·프로젝트 중심 메뉴는 이번 결정으로 대체합니다. 예전 디자인 자료는 이력으로 남기고, 간결한 설정 행·목록과 상세·입력 보존 등 맞는 패턴만 재사용합니다. 사용자 대화와 화면 캡처는 공개 저장소에 올리지 않습니다.
